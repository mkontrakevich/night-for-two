## Схема на сегодня

```text
Telegram Mini App (mobile, fullscreen)
      |
      v
Cloudflare Worker (guest auth + theatre state + AI Stranger)
      |-- OpenRouter ONLY from Worker (optional)
      |-- Workers AI (dialogue fallback; theatre generation)
      |-- Cloudflare Workflow -> R2 private theatre image/state
      |
      +-- Existing application API through Cloudflare VPC -> Node/PostgreSQL origin
              |-- photo-based identity profile + photo references
              |-- casting photo approval and canonical looks
              |-- novel / chapters / selections / library
```

## Архитектурные блокеры полного отказа от Windows origin

1. **Актёр:** исходные фотографии и идентификация пока записываются в PostgreSQL через `/novel2/api/character/build`; подготовка задания, callback и утверждение карточки ещё используют origin. При этом само AI-изображение уже выполняется в Cloudflare Workflow.
2. **Проза и роман:** книги, сценарии, ролевая авторизация, история ходов и статусы игровых персонажей зависят от Node + PostgreSQL. Убрать VPC сейчас = сломать существующие романы.
3. **Долговременное состояние:** для `novel2_*` требуется проектирование схемы D1 и миграция исторических данных с проверкой целостности.
4. **Соответствие внешности:** 1–3 фотографии — исходник узнаваемости; нельзя заменять реальные черты без согласия гостя. Событийные наряды — отдельные производные образы, а не повторная регистрация личности.
5. **Стоимость AI:** фактические расходы OpenRouter и Workers AI пока не собраны в единую телеметрию. Нельзя интерпретировать число вызовов как стоимость без цен модели и usage.

## Миграционный план, без дублирования функционала

**M1. Identity R2:** перенести загрузку исходных фото напрямую в приватный R2, добавить модель согласия/сроков удаления, ограничение количества и размера, сохранить существующий `identity` контракт UI. Проверить обработку растров, EXIF и фотозагрузку на iOS.

**M2. Actor Workflow:** вынести prepare/status/approve и сохранение эталонной карточки в Worker + Workflow + R2/D1 с idempotency key; запретить повторный AI inference при сбоях записи. Перенести выбранную карточку как единый `Identity Lock`.

**M3. Story D1:** перенести `novel2_*` из PostgreSQL в D1 по инкрементальной миграции с контрольными суммами и rollback. Проза и иллюстрации вызываются Worker API; при отсутствии второго человека оставлять штатного AI-героя без раскрытия личности.

**M4. Cutover:** проверка полного пользовательского пути на iPhone (инвайт → место → мир → фото → карточка → подтверждение → роман), затем отключение origin/VPC и удаление оставшихся прямых OpenRouter конфигураций.

## Приёмочные критерии

- Авторизация закрытого театра работает без origin; чужие роли/изображения недоступны.
- После перезагрузки приложения или падения origin состояния и готовые изображения доступны из Cloudflare.
- Выбор уже созданного мира не запускает вторую платную генерацию.
- Для актёрской карточки доступны просмотр в полный экран, подтверждение, регенерация и замена исходников.
- Изменение внешнего образа сцены не меняет лица и пропорции утверждённого актёра.
- Реальные данные второго игрока раскрываются только с его разрешения; вымышленный герой раскрывается сюжетом.
- GitHub CI/CD развертывает Worker, Workflows, R2/D1 миграции и проверяет все переходы.
- После cutover нет обязательного Windows сервера, VPC tunnel, прямых OpenRouter вызовов из Node или браузера.
