# Night for Two — изолированный контур тестирования моделей

## Целевое действие
В мини-приложении Telegram пользователь загружает UTF-8 TXT-файл, выбирает текстовые модели и отдельно подтверждает запуск. Результаты — описания кадров и промпты для графических моделей — записываются в Google Drive. Запросы к OpenRouter потенциально платные. Генерация изображений — отдельное действие.

## Подтверждённая конфигурация Google Drive (04.11.2026)
- Google OAuth и Drive API подключены; Worker `night4two-drive-oauth` записал тестовый файл `Night4two_Drive_Test.txt`.
- Папка, созданная приложением: `1bIPieVNexv8VeFRUffhsYOG0KPJ305vs`.
- Физическое размещение: `Ai Projects / Проекты / interactive-novel / 05_Тесты_моделей / Night4two — AI Model Test Files`.
- Предоставленное Google-разрешение: `drive.file` (без доступа ко всем файлам).
- Refresh token хранится в зашифрованном виде в Cloudflare Workers KV `night4two-drive-oauth`, не в репозитории и не в коде бота.

## Изоляция и обмен данными
`novel2-preview` (draft PR #112) → HTTPS POST `/api/drive/ingest` → `night4two-drive-oauth` → Google Drive.

Для связи двух Workers выпущен отдельный случайный секрет из 32 байт:
- на OAuth Worker: `INGEST_KEY` (Cloudflare Secret);
- на отправителе `novel2-preview`: `MODEL_TESTS_DRIVE_INGEST_KEY` (Cloudflare Secret).

Оба привязаны без показа содержимого в чатах или GitHub. В основном боте больше НЕ требуются `MODEL_TESTS_GOOGLE_CLIENT_ID`, `MODEL_TESTS_GOOGLE_CLIENT_SECRET` и `MODEL_TESTS_GOOGLE_REFRESH_TOKEN`.

Адаптер: `cloudflare/novel2-preview/src/model-test-drive.js`. Обработчик: `cloudflare/night4two-drive-oauth/src/index.js`. Исходный и результирующий файлы имеют уникальные имена `model-test-{jobId}-source.txt` и `model-test-{jobId}-result.json`; Cloudflare KV записывает ID загрузок. Неопределённые записи не повторяются автоматически; повторение запроса по тому же ключу возвращает подтверждённый файл, если его ID сохранён.

## Состояние внедрения
- **Готово:** OAuth и изолированное хранилище; тестовая запись Google Drive; перенос папки; публикация backend-обработчика; Cloudflare-секреты связи; адаптер в черновике GitHub PR #112.
- **Не подтверждено:** реальный Telegram→OpenRouter→Drive тест через mini-app, регрессия активного приложения, работа Durable Objects после рестартов, бюджетные лимиты и окончательное включение интерфейса.
- **Раздел тестов остаётся выключенным**: `MODEL_TESTS_CLOUD_ENABLED` не включать до завершения проверок. Не деплоить `wrangler.jsonc` из PR с placeholder VPC/D1 поверх действующего Worker.

## Проверки и ограничения
Локальные/CI-тесты с моками проверяют OAuth-ingest, границы доступа, валидацию имени, исключение повторной записи, загрузку TXT, подтверждение платного запуска, отказ модели и сбой OpenRouter. Это НЕ заменяет сквозной staging-тест. Экспорт исходника до 64 КБ, ответов — до 2 МБ текста на файл. При обрыве после записи Google и до записи ID в KV результат считается неопределённым; ручной аудит обязателен перед повтором.
